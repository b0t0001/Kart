# Kart iPad App, Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The complete Kart iPad app (Welcome → Greeting → Shopping → Checkout → Receipt, the avatar, cards, the debug panel) running on a mock backend and a scripted mock voice, demoable end to end in the iPad simulator with no network.

**Architecture:** All logic and models live in a local Swift package, `KartCore`, tested on the Mac with `swift test`: contract models, a mock backend that imitates the Supabase rules, card derivation, matching, the trip router, the mock agent brain and voice session, simulated payment, and the `AppModel` that orchestrates them. The SwiftUI app target `Kart` holds only views, the design system, and the platform sounds and speech, and is verified with simulator screenshots. The app reads state from `@Observable` objects behind the `KartBackend` and `VoiceSession` protocols, so milestone 2 (Supabase) and milestone 3 (Cartesia Line) swap in real implementations without touching views.

**Tech Stack:** Swift 6 (tools 6.2), SwiftUI, Observation, Swift Testing, iPadOS 26 / macOS 26, XcodeGen, AVFoundation. No third-party packages in this milestone.

**Spec:** `ios/docs/specs/2026-10-24-ipad-app-design.md` (read it first, especially §3). Contract: `<repo>/docs/CONTRACT.md` v0.5 (§2 catalog, §3 database, §5/§5a iPad).

## Global Constraints

- Work only inside `ios/`. Commit only `ios/` paths: `git add <paths> && git commit -m "<subject>" -- ios/`. Never stage or commit another chat's files, never switch branches (three chats share this checkout). Every commit message ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Subjects start with `ios: `.
- iPadOS deployment target 26.0, landscape only, iPad only (`TARGETED_DEVICE_FAMILY = 2`); `KartCore` platforms `.iOS(.v26), .macOS(.v26)`.
- The catalog file is `<repo>/data/store.json` (owned by the backend chat; read it, never edit it). The app bundles it; tests read it in place.
- The app never does price math for display: prices, `deal_label`, totals, and savings come from `CartState`. Only `MockKartBackend` computes prices, because it imitates the backend.
- Names: `short_name` (`Product.shortName`) in compact UI and everything Kart says; the full `name` only on the checkout bill.
- Money is `Decimal`, shown with `Money.format` ("$12.99").
- Every public model struct declares an explicit `public init` with all stored properties in declaration order, with optional properties defaulting to `nil` (tests construct them), and its stored properties are `var`.
- The mock imitates the backend **as built** (contract v0.8 §3a, backend commit `4feb9ba`). Where this plan and §3a disagree, §3a wins; tell the iPad chat's owner.
- One test/demo clock: `@MainActor public final class ManualClock { public var now: Date; public init(now: Date = Date(timeIntervalSince1970: 1_800_000_000)) }` in `Sources/KartCore/Backend/ManualClock.swift` (Task 3). Mocks take `clock: @escaping @MainActor () -> Date`; tests pass `{ clock.now }`.
- Type: SF Pro Rounded (`.system(…, design: .rounded)`); body ≥ 20 pt, nothing below 17 pt, key numbers ≥ 40 pt; touch targets ≥ 64 pt; at most one primary (filled) button per screen; light mode only.
- Motion: state changes animate with `Theme.spring` (`.spring(response: 0.45, dampingFraction: 0.82)`); nothing pops in without a transition.
- Simulator: `iPad Pro 13-inch (M5)`. Bundle id `com.kart.app`.

## Review Focus

1. **Double taps on Pay** (an excited judge): payment must run once. Tested in Task 8 (`payTwiceChargesOnce`).
2. **A product id the bundled catalog doesn't know** (the merchant added one after the build): the cart line still renders from `CartItem.name`, and next-stop logic skips it instead of crashing. Tested in Task 6 (`nextStopSkipsDoneAndUnknownProducts`), and in Task 11 by the `CartItem.name` fallback.
3. **A `carts` row without the proposed fields** (`status`, `savings`, `location`, `trip_started_at`, before the backend ships P2/P3/P8): decoding must succeed with defaults. Tested in Task 2 (`decodesCartRowWithoutProposedFields`).
4. **Removing something that was never added, or the same item twice quickly:** quantities never go negative, and a removal of an absent product is a no-op. Tested in Task 3 (`removingAbsentProductIsNoOp`, `secondUnitIncrementsQty`).
5. **A trip reset mid-flow** (debug reset, or a new shopper while a card or payment is open): stale cards and payment state vanish, and the reset isn't announced as removals. Tested in Task 6 (`tripChangeProducesNoChanges`) and Task 8 (`startTripClearsStaleState`).

- Produces:
  Field names follow contract v0.8 §3 and §3a (as built by the backend in `4feb9ba`). Fields marked `?` are optional so a row missing them still decodes.
  - `enum TripStatus: String { idle, shopping, checkout, paid }`
  - `struct CartItem: Identifiable { productId, name: String; shortName: String?; price: Decimal; listPrice: Decimal?; qty: Int; dealLabel: String?; dealId: String?; section: String?; addedAt: Date; lastAddedAt: Date?; var id: String /* productId: one line per product */ }`
  - `struct PlanItem: Identifiable { productId, reason: String; qty: Int /* default 1 */; done: Bool; name: String?; section: String?; aisle: String?; inStock: Bool?; dealLabel: String?; var id: String /* productId */; init(productId: String, reason: String, qty: Int = 1) /* convenience: what the agent sends */ }`
  - `struct Suggestion { productId, dealId, text: String; name: String?; dealLabel: String?; aisle: String?; section: String?; price: Decimal?; salePrice: Decimal?; offeredAt: Date? }`. `text` is a complete spoken line, e.g. `"Parmesan is $3 off in Aisle 4. Want it?"`.
  - `struct CartLocation { section, source: String; at: Date }`
  - `struct CartState { cartId: String; tripId: UUID?; items: [CartItem]; itemCount: Int; total: Decimal; savings: Decimal?; plan: [PlanItem]; nextStep: String?; suggestion: Suggestion?; suggestedDeals: [String]; status: TripStatus; tripStartedAt: Date?; location: CartLocation?; updatedAt: Date?; static func empty(cartId: String) -> CartState }`. When missing, `itemCount` defaults to Σ qty, `suggestedDeals` to `[]`, and `status` to `.idle`.
  - `enum CartEventType: String { added, removed }`, `enum CartEventSource: String { vision, manual }`
  - `struct CartEvent: Identifiable { id: Int64; eventId: UUID; cartId: String; tripId: UUID?; type: CartEventType; productId: String?; confidence: Double; source: CartEventSource; label: String?; snapshotUrl: URL?; applied: Bool?; createdAt: Date; resolvedAt: Date?; var needsConfirmation: Bool }`. `needsConfirmation` = vision source, added, unresolved, and not applied (`applied == false`, or `productId == nil` when `applied` is missing).
  - `struct TranscriptLine: Identifiable { enum Role: String { user, agent }; id: Int64; role: Role; text: String; createdAt: Date }`
  - `struct Receipt { id: Int64?; cartId: String; tripId: UUID?; total, savings: Decimal; itemCount, durationS: Int; provider, status: String /* "paid" | "failed" */; items: [CartItem]; createdAt: Date? }`
  - `enum KartJSON { static func decoder() -> JSONDecoder }`
  - `enum Money { static func format(_ amount: Decimal) -> String; static func compact(_ amount: Decimal) -> String }`
  - `enum TripFormat { static func durationPhrase(seconds: Int) -> String; static func receiptHeadline(savings: Decimal, durationS: Int) -> String }`

  All of these are public; the models are `Codable`, `Sendable`, and `Equatable`. Keys use `convertFromSnakeCase`, so `snapshot_url` maps to `snapshotUrl` and `duration_s` to `durationS`.

**Mock rules this task pins** (they imitate the backend's `apply_cart_event`; the spec says the real backend owns them):
- **Effective price:** `amount_off` → `max(0, price − value)`; `percent_off` → `price × (100 − value) / 100`, rounded to cents (`.plain`).
- **One line per product** (`CartItem.id = productId`). The first add creates the line: `price` = effective price, `listPrice` = catalog price, `dealLabel`/`dealId` from the active deal, `shortName` and `section` from the catalog, and `addedAt` = `lastAddedAt` = now. Later adds increment `qty`, set `lastAddedAt`, and keep `price = min(line price, current effective price)`. A removal decrements `qty`, drops the line at 0, and is a no-op if the product isn't in the cart (the event is still recorded).
- `total = Σ price × qty`; `savings = Σ (listPrice − price) × qty`; `itemCount = Σ qty`.
- **Plan fill:** for each plan line, `name` = shortName, `section`, `aisle` = the section's `aisleLabel`, `inStock = stock > 0`, `dealLabel` = the active deal's label, and `done = cart qty ≥ plan qty`. Lines whose product isn't in the catalog keep only what was sent, stay not-done, and go last.
- **Plan order (walking route)**, recomputed after `setPlan` and after every cart change. Done lines come first, in their previous order. The remaining lines follow, greedily picking the nearest section by `|center x − current x|` (center x = `x + w/2`), starting from the location section's center or else the entrance `x`; ties keep their previous order.

- **Events:** each gets `eventId = UUID()` and `tripId` = the current trip, and ids count up from 1 within a trip. An applied add sets `location = CartLocation(section: product.section, source: "item", at: now)`. A vision event whose `productId` is nil or not in the catalog is recorded with `applied = false` and changes nothing else.
- **`startTrip()`:** new `tripId`; items, plan, suggestion, `suggestedDeals`, events, and transcript cleared; `total`, `savings`, and `itemCount` 0; `location` and `nextStep` nil; `status = .shopping`; `tripStartedAt = now`.

**Rules:**
- **Suggestions:** after an applied add of product P, if no suggestion is open, offer the first active deal (in catalog order) whose `pairsWith` contains P, whose product is neither in the cart nor in the plan, and whose id isn't in `suggestedDeals`. The offer is `Suggestion(productId, dealId, text: "\(shortName) is \(label) in \(aisleLabel). Want it?", name: shortName, dealLabel: label, aisle: aisleLabel, section, price: list price, salePrice: effective price)`, and its deal id is appended to `suggestedDeals`, so it's never offered twice in a trip.
- **Clearing:** the suggestion clears on `dismissSuggestion()`, when its product is added, or when `setPlan` includes its product.
- **Every offer sets `offeredAt = now`.**
- **Store-created deals replace the suggestion** (contract v0.9). When `pushDeal` creates a deal whose id wasn't in the catalog, and it's eligible (some cart product is in its `pairsWith`; its product isn't in the cart or plan; it isn't in `suggestedDeals`), it replaces the current suggestion (or fills an empty one) with `offeredAt = now`, and is appended to `suggestedDeals`. Pushing an update to an existing deal never replaces.
- **P10:** after `pushDeal` or `removeDeal`, every line's `price` becomes `min(line price, new effective price)`, refreshing `dealLabel`/`dealId` when the price drops. So drops reach items already in the cart, and increases never do. Then `total`, `savings`, the plan fill, and `nextStep` are recomputed.
- **`checkout`:** throws `.unresolvedItems(count:)` while any event of this trip `needsConfirmation`. If this trip already has a receipt, it returns that same receipt. Otherwise it creates `Receipt(id: 1, cartId, tripId, total, savings, itemCount, durationS: Int(now − tripStartedAt), provider, status: "paid", items: cart.items, createdAt: now)` and sets `status = .paid`.
- **`setStatus`:** sets idle, shopping, or checkout; `.paid` throws `.invalidStatus`. `endTrip` = `setStatus(.idle)`.

**Rules:**
- **`cards`:** `CardDeriver.cards` with `voiceOnline = voice.state != .offline`, `now = clock()`, and this model's `locallyResolved`, `baselineDeals`, and `acknowledgedNewDeals`.
- **`startTrip`:** clears local state (`locallyResolved`, `acknowledgedNewDeals`, `paymentState = .idle`, `highlightUnresolved = false`, `celebration = nil`); calls `backend.startTrip()`; sets `baselineDeals` from the catalog; awaits `voice.start(cartId:tripId:)`; sends `.tripContext`; reaction `.wave`; `lastActivity = now`.
- **`ingest(cart:)`** diffs against the previous cart (`CartDiff`):
  - `.added` → sound `.added`, `voice.send(.cartChanged)`, and reaction `.happyBounce` if the product is in the plan.
  - `.removed` → sound `.removed`, plus `send`.
  - `.priceDropped` → `celebration = "\(shortName) just dropped \(Money.compact(from − to)). You saved."`, plus `send`.
  - A new non-nil `suggestion` (a different `dealId` from last time, including one the store just created that replaced an open card): if that deal isn't in `announcedDeals`, play sound `.card`, `send(.suggestion)`, set reaction `.happyBounce`, insert it into `announcedDeals`, and drop any queued announcement for it.

- **`ingest(events:)`:** a newly seen event that needs confirmation → sound `.card`, reaction `.curiousTilt`.
