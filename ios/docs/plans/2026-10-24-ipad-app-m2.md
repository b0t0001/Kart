# Kart iPad App, Milestone 2 Implementation Plan (Supabase)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Written overnight on 2026-10-24 under the manager's relay of Dylan's "build everything" instruction (see `ios/docs/OVERNIGHT.md`). Review it with the milestone 1 plan.

**Goal:** The same app, on the real backend: realtime cart, events, catalog, captions and receipt from Supabase, every intent through the contract's RPCs, running in the iPad simulator against the local stack at `http://127.0.0.1:54321`.

**Architecture:** A new `KartSupabase` library target inside the `KartCore` package, so `KartCore` itself stays dependency-free. It contains a small PostgREST client (URLSession) and a minimal Supabase Realtime client (the Phoenix protocol over `URLSessionWebSocketTask`, the same handshake as `backend/e2e/realtime.py`). `SupabaseKartBackend` conforms to `KartBackend` and treats realtime as a **change signal only**: any change on a table triggers a debounced REST refetch of that slice. That way there's no payload decoding, no ordering races, and a reconnect simply refetches everything. The app picks the backend at launch; the mock stays the offline fallback.

**Tech Stack:** Swift 6, URLSession and its WebSocket task, Swift Testing (with `URLProtocol` stubs plus a live integration suite gated by `KART_IT=1`). No third-party packages.

**Spec:** `ios/docs/specs/2026-10-24-ipad-app-design.md` §4. Contract: `docs/CONTRACT.md` v0.9 §3, §3a, §5a. Backend reference: `backend/README.md`, `backend/docs/LOCAL_SUPABASE.md`.

## Global Constraints

- Everything from the milestone 1 plan's Global Constraints still applies (paths, commits, design rules).
- **No secrets in git.** `ios/Config.xcconfig` is generated from `/Users/dylan/Documents/GitHub/kart/.env` by `ios/scripts/make-config.sh` and is gitignored. Only `SUPABASE_URL`, `SUPABASE_ANON_KEY` (public by design), and `CART_ID` go into it; never the service-role key.
- **Reads:** anon key, `apikey` + `Authorization: Bearer` headers. `products?active=is.true`, `deals?active=is.true`, `carts?cart_id=eq.<id>`, `cart_events?cart_id=eq.<id>&trip_id=eq.<trip>&order=id`, `transcript?cart_id=eq.<id>&trip_id=eq.<trip>&order=id`, `receipts?cart_id=eq.<id>&trip_id=eq.<trip>`.
- **Writes:** RPCs only, `POST /rest/v1/rpc/<name>` with named `p_*` parameters exactly as in `backend/README.md`.
- **The checkout block:** a PostgREST error whose `message` starts with `unresolved_items:` maps to `KartBackendError.unresolvedItems(count:)`, taking the number after the colon.
- **ATS:** `NSAppTransportSecurity › NSAllowsLocalNetworking = YES` (for local http). Hosted https needs nothing.
- **Backend choice at launch:** `-KartBackend mock|supabase`. With no argument, use Supabase when the Config has a URL and key, else the mock. `-KartScenario` forces the mock.

## Review Focus

1. **Realtime drops or never confirms the join:** the app must still converge. Refetch on every (re)join, and poll every 5 s while realtime isn't confirmed (`connection = .reconnecting`).
2. **A trip changes underneath the app** (reset from the laptop, or another iPad): events, transcript and receipt refetch for the new `trip_id`, and `AppModel` sees one new cart, not a diff.
3. **An RPC fails** (network, 4xx): intents throw, and no state changes locally until the refetch shows the backend's truth.
4. **Numbers arrive as JSON numbers** (`9.99`, `0.00`) and timestamps carry microseconds: decoding goes through `KartJSON` only.
5. **App relaunched mid-trip:** `resumeTrip()` adopts the state silently, and the voice resumes instead of re-greeting.

### Task 3: Realtime change signals

**Files:** Create `KartCore/Sources/KartSupabase/RealtimeSignals.swift`: `final class RealtimeSignals { init(url: URL, anonKey: String); func watch(table: String, filter: String?) -> AsyncStream<Void>; func start(); func stop(); var onStatus: (@Sendable (Bool) -> Void)? }`, one socket and one channel per watched table. Protocol, per `backend/e2e/realtime.py`:
- Connect to `ws(s)://…/realtime/v1/websocket?apikey=<anon>&vsn=1.0.0`.
- `phx_join` with `config.postgres_changes [{event:"*", schema:"public", table, filter}]` and `access_token`.
- The join is confirmed by a `system` message with status `ok` and "Subscribed".
- Each `postgres_changes` message yields `()`.
- Heartbeat every 25 s: topic `phoenix`, event `heartbeat`.
- On close or error: report status false, reconnect with backoff (1, 2, 4 … 15 s), and rejoin everything.

Test: `Tests/KartSupabaseTests/RealtimeSignalsTests.swift`: the join-message encoding and the system-message classifier as pure functions (`static func joinMessage(...) -> Data`, `static func classify(_ data: Data) -> Event`), plus an `IT` test (gated by `KART_IT=1`) that watches `carts` filtered to `cart_id=eq.7`, calls `reset_cart` over REST, and expects a signal within 5 s.

### Task 4: `SupabaseKartBackend`

**Files:** Create `KartCore/Sources/KartSupabase/SupabaseKartBackend.swift`: `@MainActor @Observable final class SupabaseKartBackend: KartBackend { init(url: URL, anonKey: String, cartId: String, fallbackLayout: StoreLayout); func start() async; func stop() }`. Test: `Tests/KartSupabaseTests/SupabaseKartBackendIT.swift` (gated by `KART_IT=1`).

**Rules:**
- **`start`:** fetch catalog, cart, then the trip slices; watch `carts` (filter `cart_id=eq.<id>`), `cart_events` (same filter), `transcript` (same), `receipts` (same), `products`, and `deals`. A signal refetches that slice after a 150 ms debounce.
- **Trip changes:** a cart refetch with a different `trip_id` also refetches events, transcript and receipt.
- **`connection`:** `.reconnecting` until every join is confirmed, and whenever the socket drops. While reconnecting, poll every 5 s.
- **Catalog:** `products` and `deals` (active only) mapped onto `Catalog`, with the bundled `store.json` layout. Deals keep `pairsWith` and `endsAt`.
- **Intents and their RPCs:**

  | Intent | RPC call |
  |---|---|
  | `startTrip` | `reset_cart` |
  | `applyManualEvent` | `apply_cart_event(p_type, p_product_id, p_confidence: 1, p_source: "manual", p_label: nil, p_event_id: new UUID, p_method: "manual", p_resolves_event_id)` |
  | `resolveUnknown` | the same, with `p_type: "removed"`, `p_product_id: null` |
  | `setPlan` | `set_plan(p_plan: [{product_id, reason, qty}])` |
  | `dismissSuggestion` | `dismiss_suggestion` |
  | `setStatus` | `set_cart_status` (`.paid` throws `.invalidStatus` without calling) |
  | `checkout` | `checkout(p_provider)` → `Receipt`, mapping `unresolved_items:` |
  | `endTrip` | `set_cart_status(idle)` |
  | `appendTranscript` | `append_transcript` |

  After each intent, refetch the cart immediately; don't wait for realtime.
- **Debug levers** (for the debug panel on the real backend): `simulateVision(_:productId:confidence:label:)` = `apply_cart_event` with `p_source: "vision"`, `p_method: "local"`. Merchant deal levers stay mock-only (merchant writes need the service role); use `backend/cart.py deal …` or the merchant console.

IT test, against the local stack:
1. `startTrip` → status `.shopping`.
2. `setPlan(pasta)` → plan filled and route-ordered.
3. `simulateVision` spaghetti → a suggestion appears.
4. An unknown add → `checkout` throws `.unresolvedItems(1)`.
5. `resolveUnknown` → `checkout` returns a receipt with `status "paid"`.
6. `endTrip` → `.idle`.
7. Realtime: after `backend/cart.py add bananas` from outside (a subprocess), `cart.items` contains bananas within 3 s.
